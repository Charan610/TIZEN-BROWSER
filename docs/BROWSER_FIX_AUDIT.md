# Comprehensive Browser Architecture & Failure Audit

**Target Platform**: Samsung Smart TV (2022 model, Tizen 6.5, Chromium M85)  
**Package Type**: Tizen Web Application (`.wgt`)  
**Audit Date**: October 2026  
**Rollback Tag**: `v1.0.3-wgt-rollback` (Git branch: `wgt-original-backup`)

---

## 1. Executive Summary

This audit investigates why the existing Samsung TV Browser application fails to browse websites in-app and instead displays errors, blank surfaces, or delegates navigation to the external Samsung Internet application.

The application possesses a finished UI (dark theme, top omnibox toolbar, start page, bookmark management, history store, settings modal, spatial navigation, and virtual pointer), but its core web browsing engine is fundamentally broken because it relies on HTML `<iframe>` embedding inside a `.wgt` container and delegates standard HTTP/HTTPS navigation to Samsung Internet via `tizen.application.launchAppControl`.

## 2. Source Code Traversal & Component Identification

### 2.1 Address Bar Implementation
- **Files**:
  - `index.html` (lines 43–64): Top navigation toolbar `#app-toolbar` containing input `#toolbar-address-input` and search button `#toolbar-search-go`.
  - `src/ui/toolbar.js` (lines 31, 102–112): `Toolbar.init()` queries `#toolbar-address-input` and binds it using `TextInput.bind()` and `Suggestions.attach()`.
  - `src/ui/start_page.js` (lines 35–42): Homepage search input `#start-search-input` and button `#start-search-btn`.
- **Behavior**: User inputs text either in the homepage search box or the top toolbar omnibox.

### 2.2 Search Suggestion Service
- **File**: `src/ui/suggestions.js`
- **Behavior**:
  - Listens to `input` and `focus` events on `#toolbar-address-input` and `#start-search-input`.
  - Debounces input by 200 ms (`handleInputChange`).
  - Aggregates local bookmarks (`BookmarkManager.getAll()`) and local history (`HistoryManager.getAll()`).
  - Dispatches an asynchronous `fetch()` query to Google Suggest API:  
    `https://suggestqueries.google.com/complete/search?client=chrome&q=${encodeURIComponent(query)}`
  - Formats results into a dropdown list (`#suggestions-dropdown`) with keyboard/remote navigation.

### 2.3 Input Submission & Enter / Done Key Handling
- **File**: `src/input/text_input.js`
- **Behavior**:
  - Intercepts key events on text inputs:
    - Keycode `65376` (Samsung TV virtual keyboard "Done"): triggers single submit callback.
    - Keycode `13` (Physical Enter / Remote OK): triggers submit if not composing and input is non-empty.
    - Keycodes `65385` (Samsung IME Cancel), `10009` (Tizen Back), `27` (Escape): blurs input and hides suggestions.
  - On submission, calls `onSubmit(committedText)`, which routes to `Toolbar.callbacks.onNavigate(value)` -> `App.navigateTo(input)`.

### 2.4 URL Normalization Logic
- **File**: `src/browser/url_utils.js` (`UrlUtils.normalizeInput`)
- **Behavior**:
  - Checks `isUnsafeScheme`: blocks `javascript:`, `data:`, `vbscript:`, `file:`, `about:blank`.
  - Evaluates `isUrl`:
    - Checks regex for domain name `^([a-z0-9]...)+[a-z]{2,}(:\d+)?([/?#].*)?$`.
    - Checks regex for IPv4 address `^(\d{1,3}\.){3}\d{1,3}(:\d+)?([/?#].*)?$`.
    - Checks `localhost(:\d+)?([/?#].*)?$`.
  - If recognized as URL, prepends `https://` if missing.
  - If not recognized as URL (or contains whitespace), wraps query into search engine URL:
    `engine.searchUrl + encodeURIComponent(trimmed)` (defaults to DuckDuckGo or Google).

### 2.5 Iframe Elements and Sandboxing
- **File**: `src/browser/viewport.js` (lines 35–45)
- **HTML Structure**:
  ```html
  <div id="viewport-iframe-wrapper" class="viewport-surface hidden">
    <iframe id="web-surface"
            sandbox="allow-scripts allow-forms allow-same-origin"
            allow="fullscreen; autoplay; encrypted-media"
            referrerpolicy="no-referrer-when-downgrade"></iframe>
  </div>
  ```
- **Limitation**:
  - The iframe is the sole in-app web rendering element in the `.wgt` app.
  - Major search engines (`google.com`, `bing.com`) and top sites (`youtube.com`, `github.com`, `wikipedia.org` login) explicitly reject iframe embedding via `X-Frame-Options: SAMEORIGIN` / `DENY` and CSP `frame-ancestors 'none'`.

### 2.6 Window.open() Interception
- **File**: `src/adblock/popup_shield.js` (lines 22–27)
- **Behavior**:
  - Monkey-patches `window.open` in the parent window.
  - However, because third-party websites run inside a sandboxed cross-origin iframe (or externally in Samsung Internet), this parent patch has zero effect on popups generated by scripts inside the framed web page!

### 2.7 Tizen appControl Launches & External Browser Fallback
- **File**: `src/browser/viewport.js` (lines 104–109, 111–147)
- **File**: `src/browser/system_browser.js` (lines 6–34)
- **Behavior Tracing**:
  ```javascript
  // In Viewport.loadUrl(url, mode):
  if (mode === 'READER') {
    this.loadReaderView(url);
  } else if (mode === 'EMBED' || !/^https?:\/\//i.test(url)) {
    this.loadEmbedView(url);
  } else {
    this.loadBrowserView(url); // <-- ALL NORMAL HTTP/HTTPS URLS HIT THIS!
  }
  ```
  - When `loadBrowserView(url)` executes:
    1. It hides all internal surfaces.
    2. It renders an error card: *"Samsung Internet: Opening your page in the TV browser... Open in Samsung Internet"*.
    3. It calls `SystemBrowser.open(url)`.
    4. `SystemBrowser.open(url)` instantiates:
       `new tizen.ApplicationControl('http://tizen.org/appcontrol/operation/view', parsed.href)`
    5. It invokes `tizen.application.launchAppControl(control, null, ...)`.
  - **Result**: Every search and every website navigation systematically exits the application and launches Samsung's native Internet app!

## 3. Root Cause Analysis of Current Failures

| Observed Failure | Root Cause in Codebase | Technical Platform Mechanism |
|---|---|---|
| **Entering a search query displays page-not-found or launches external browser** | `Viewport.loadUrl` defaults all `http://`/`https://` URLs to `loadBrowserView(url)`. | `SystemBrowser.open` invokes `launchAppControl` with operation `view`. If the TV cannot find an app control handler or fails, an error dialog appears. If it succeeds, the app is backgrounded. |
| **Entering `google.com` displays blank or fails** | In `EMBED` mode, `Viewport.loadEmbedView` sets `<iframe id="web-surface" src="https://google.com">`. | Chromium M85 enforces HTTP response header `X-Frame-Options: SAMEORIGIN`. The browser engine refuses to render Google inside the iframe, triggering a timeout watchdog after 12s that displays "Site Embedding Limitation". |
| **Clicking links launches Samsung Internet** | Any standard link navigation routed through `App.navigateTo()` calls `Viewport.loadUrl(url)` with no mode specified, triggering `loadBrowserView`. | The code intentionally bypassed iframe loading because the previous developer gave up on solving iframe header restrictions. |
| **Websites cannot be interacted with (no remote scroll/focus)** | When a page does load in an iframe (e.g. `example.com`), cross-origin security prevents parent JavaScript from accessing `iframe.contentWindow.document`. | Cross-origin Same-Origin Policy (SOP). The parent app cannot inspect the DOM, inject focus handlers, capture scroll keys, or dispatch synthetic click events. |
| **Ad and popup blocking cannot work** | Adblock logic (`AdBlockEngine`, `PopupShield`, `CosmeticRules`) runs exclusively in the parent application context. | Tizen Web Application API (`.wgt`) exposes no WebRequest or network interception API for sub-frames. Cosmetic filters can only be injected into `same-origin` frames (which third-party websites never are). |

## 4. The Architectural Impasse of Pure `.wgt` for Full In-App Browsing

1. **Security Policy**: W3C / Chromium security models enforce `X-Frame-Options` and CSP `frame-ancestors` inside web engines. A `.wgt` is a packaged Web Application running on Chromium M85. It is subject to standard Web platform restrictions unless native extensions exist.
2. **Missing Network Interception**: In `.wgt`, there is no `chrome.webRequest` or `webRequest` API.
3. **No Embedded WebView Control in Web Runtime**: A JavaScript web app cannot instantiate a nested Chromium-EFL browser instance (`Tizen.WebView`) directly from JavaScript.
4. **Conclusion**: A pure `.wgt` application relying solely on HTML `<iframe>` **cannot** serve as a general-purpose, in-app web browser for arbitrary modern websites (such as Google, YouTube, GitHub, or Wikipedia).

To achieve genuine in-app web browsing with tabs, remote control interaction, page navigation events, and script-level popup/ad protection on Samsung TV 2022 (Tizen 6.5 / Chromium M85), the application must utilize Tizen's native browser hosting architecture (`Tizen.WebView` / Chromium-EFL) as demonstrated by Overscan, while preserving the application's visual identity, UI controls, search suggestions, bookmarks, and settings.
